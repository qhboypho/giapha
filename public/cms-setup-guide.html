Hướng dẫn setup CMS gia phả cho khách mới

Quy trình này dùng khi clone base gia phả, tạo tài nguyên Cloudflare mới, import CMS package và deploy website cho một dòng họ/khách mới.

Setup nhanh bằng một command

Dành cho người không chuyên kỹ thuật hoặc lúc cần dựng nhanh một site khách mới. Chỉ cần đăng nhập Cloudflare trước, sau đó chạy một command từ repo base. 

cd C:\Users\DinhTungPC\.gemini\antigravity\scratch\giapha-tc
npm run customer:setup -- --family-name="Trần Công" --slug=tran-cong --admin-password="TranCong@2026" --deploy

Nếu folder local khách đã tồn tại và muốn tạo lại từ đầu:

npm run customer:setup -- --family-name="Trần Công" --slug=tran-cong --admin-password="TranCong@2026" --deploy --force

Mặc định project khách vẫn giữ Setup Wizard để khách tự cấu hình. Nếu đã setup xong và muốn bàn giao bản gọn:

npm run customer:setup -- --family-name="Trần Công" --slug=tran-cong --admin-password="TranCong@2026" --deploy --force --handoff-ready

Trước khi chạy

  • Máy đã cài Node.js 20+ và npm.
  • Đã đăng nhập Cloudflare Wrangler bằng tài khoản có quyền tạo Pages, D1, R2.
  • Đang đứng ở folder repo base giapha-tc.
  • Đổi family-name, slug và admin-password theo khách thật.
npx wrangler login

Command sẽ tự làm gì

  • Tạo folder project khách nằm ngang hàng repo base.
  • Cài dependencies bằng npm install.
  • Tạo Cloudflare D1 và R2 riêng cho khách.
  • Tự lấy D1 UUID và ghi vào wrangler.jsonc.
  • Apply migrations lên D1 remote.
  • Tạo tài khoản admin bằng mật khẩu đã nhập.
  • Build và deploy Cloudflare Pages.

Kết quả sau khi chạy

Cuối quá trình, terminal sẽ in ra các thông tin cần bàn giao hoặc kiểm tra.

URL https://giapha-tran-cong.pages.dev/
Tài khoản admin / mật khẩu đã đặt
Folder local ..\giapha-tran-cong
Cloudflare D1, R2 và Pages project riêng

Sau khi site chạy được

  • Đăng nhập bằng admin.
  • Mở Setup Wizard trong app để đổi tên dòng họ, logo, footer và nội dung.
  • Import CMS package hoặc nhập dữ liệu gia phả bằng AI/JSON.
  • Đổi mật khẩu admin trước khi bàn giao khách.
  • Nếu muốn ẩn Setup Wizard sau khi cấu hình xong, tạo project bằng --handoff-ready hoặc đổi ENABLE_SETUP_WIZARD về false.
  • GitHub repo riêng là bước optional, làm sau khi site đã ổn.

1. Chuẩn bị

  • Node.js 20+ và npm.
  • Git.
  • Tài khoản Cloudflare có quyền tạo Pages, D1, R2.
  • File CMS package .json của khách.
npx wrangler login

Tab này giữ quy trình chi tiết để dev kiểm tra từng bước. Nếu muốn setup nhanh, dùng tab For non-tech.

npm run create-customer -- --family-name "Trần Công" --slug tran-cong

Nếu muốn tạo luôn git local branch và initial commit:

npm run create-customer -- --family-name "Trần Công" --slug tran-cong --git-init

Nếu tạo bản đã cấu hình xong để bàn giao và không muốn hiện Setup Wizard:

npm run create-customer -- --family-name "Trần Công" --slug tran-cong --handoff-ready

Nếu đã ở trong folder project khách rồi, chạy riêng Provision Wizard:

npm run provision:wizard

Quy trình mẫu: Họ Trần Công

Trước khi chạy git:publish-customer, cần có đủ 4 thứ:

  • Project local khách đã tạo bằng create-customer.
  • Đã vào đúng folder project khách.
  • Repo GitHub mới riêng, ví dụ qhboypho/giapha-tran-cong.
  • D1/R2 đã tạo và wrangler.jsonc đã thay cả database_id lẫn preview_database_id.

Chạy từ repo base để tạo project mới, provision, cài dependencies, ghi wrangler và commit local:

npm run create-customer -- --family-name="Trần Công" --slug=tran-cong --git-init --write-wrangler --install --force --commit-message="chore: init Tran Cong site"

Vào project mới và tạo tài nguyên Cloudflare:

cd ..\giapha-tran-cong
npx wrangler d1 create giapha-tran-cong-db
npx wrangler r2 bucket create giapha-tran-cong-media
npx wrangler r2 bucket create giapha-tran-cong-media-preview

Copy database_id vào wrangler.jsonc, rồi apply migrations:

"database_id": "370c2d40-99fe-4124-aa8f-d87e236203f1",
"preview_database_id": "370c2d40-99fe-4124-aa8f-d87e236203f1"

npx wrangler d1 list
npx wrangler d1 migrations apply giapha-tran-cong-db --local
npx wrangler d1 migrations apply giapha-tran-cong-db --remote

Tạo hoặc cập nhật admin trước khi chạy/deploy để vào trang là đăng nhập được ngay:

$env:ADMIN_BOOTSTRAP_PASSWORD="mat-khau-admin-local"
node scripts/admin-bootstrap.mjs --db=giapha-tran-cong-db --local --migrate --yes
$env:ADMIN_BOOTSTRAP_PASSWORD="mat-khau-admin-prod"
node scripts/admin-bootstrap.mjs --db=giapha-tran-cong-db --remote --migrate --yes
Remove-Item Env:ADMIN_BOOTSTRAP_PASSWORD

Lệnh này hash mật khẩu đúng chuẩn, ghi user admin vào D1 và xóa session cũ nếu có.

Sau khi wrangler.jsonc đã đúng, dùng script để commit và push lên repo GitHub riêng nếu có:

npm run git:publish-customer -- --remote-url=https://github.com/qhboypho/giapha-tran-cong.git --branch=customer/tran-cong --user-name="Dinh Tung" --user-email="you@example.com" --commit-message="chore: configure Tran Cong Cloudflare resources"

Deploy lần đầu, set secret AI, deploy lại:

npm run build
npx wrangler pages deploy ./dist --project-name giapha-tran-cong
npx wrangler pages secret put AI_CONFIG_SECRET --project-name giapha-tran-cong
npm run build
npx wrangler pages deploy ./dist --project-name giapha-tran-cong

Kết quả mẫu: https://giapha-tran-cong.pages.dev/

2. Clone source thủ công nếu không dùng Create Customer

git clone https://github.com/qhboypho/giapha.git giapha-khach-a
cd giapha-khach-a
npm install
git checkout giapha-cms
git checkout -b customer/khach-a

3. Tạo Cloudflare resources

Tạo riêng cho mỗi khách:

  • Pages project, ví dụ giapha-khach-a.
  • D1 database, ví dụ giapha-khach-a-db.
  • R2 bucket, ví dụ giapha-khach-a-media.
npx wrangler d1 create giapha-khach-a-db
npx wrangler r2 bucket create giapha-khach-a-media

Nếu dùng AI nhận diện ảnh/PDF trong app, đặt secret mã hóa một lần cho Pages project:

npx wrangler pages secret put AI_CONFIG_SECRET --project-name giapha-khach-a

Sau bước này, admin có thể vào Cấu hình AI để chọn OpenAI/Gemini/Claude và lưu API key provider đã mã hóa trong D1.

4. Sửa wrangler.jsonc

Cập nhật name, database_name, database_id, bucket_name theo khách.

{
  "name": "giapha-khach-a",
  "d1_databases": [
    {
      "binding": "DB",
      "database_name": "giapha-khach-a-db",
      "database_id": "D1_DATABASE_ID_CUA_KHACH",
      "preview_database_id": "D1_DATABASE_ID_CUA_KHACH"
    }
  ],
  "r2_buckets": [
    {
      "binding": "MEDIA_BUCKET",
      "bucket_name": "giapha-khach-a-media",
      "preview_bucket_name": "giapha-khach-a-media-preview"
    }
  ]
}

5. Kiểm tra CMS package

Lệnh dry-run chỉ validate và sinh SQL, chưa ghi DB.

node scripts/cms-bootstrap.mjs --package=./data/khach-a-package.json

Nếu chạy qua npm trên Windows/PowerShell:

npm run cms:bootstrap -- -- --package=./data/khach-a-package.json

6. Import local để test

node scripts/cms-bootstrap.mjs --package=./data/khach-a-package.json --migrate --admin-password="mat-khau-admin-local" --yes

Lệnh này apply migrations, import config/members/history và tạo/update admin.

7. Chạy app local

npm run build
npm run dev:cf

Mở http://localhost:8788, đăng nhập bằng admin và mật khẩu vừa set.

8. Kiểm tra trong UI quản trị

  • Logo, tên dòng họ, hero, footer.
  • Cây gia phả, thành viên, người tiêu biểu.
  • Lịch giỗ và lịch sử dòng họ.
  • Mobile layout.
  • Export backup bằng Xuất gói CMS.
  • Nếu có ảnh lịch sử, export/import thêm Gói media R2.
  • Nếu khách đưa ảnh giấy gia phả, dùng Nhập gia phả bằng AI để copy prompt, paste JSON và preview.

9. Import production

node scripts/cms-bootstrap.mjs --package=./data/khach-a-package.json --remote --migrate --admin-password="mat-khau-admin-prod" --yes

Lệnh có --remote và --yes sẽ ghi vào D1 trên Cloudflare. Chỉ chạy sau khi local đã ổn.

10. Deploy Pages

npm run build
npx wrangler pages deploy ./dist --project-name giapha-khach-a

Sau khi deploy, gắn custom domain nếu khách có tên miền.

11. Bàn giao

  • URL website.
  • Tài khoản admin và mật khẩu tạm thời.
  • Yêu cầu khách đổi mật khẩu sau khi nhận.
  • Hướng dẫn export/import CMS package để backup/restore.

Ghi chú về ảnh R2

CMS package v1 chứa reference ảnh, còn binary ảnh được đóng gói riêng trong media package. Quy trình chuẩn là import CMS package trước để tạo dữ liệu, sau đó import gói media R2 để upload ảnh vào đúng key mà lịch sử dòng họ đang tham chiếu.
